# Rust＋Tauri 阶段 A 验证说明

日期：2026-10-31。

> 历史阶段记录：下文描述阶段 A 首版当时的功能范围；阶段 D 自动监测与阶段 E 托盘已在后续实现。当前状态见 [Rust＋Tauri 改造计划](Rust-Tauri技术与UI改造计划.md)。

本包是技术迁移的第一步，用于确认 Rust、Tauri、Windows 采集、现有 OCR 原生库和旧数据库能够一起工作。它尚未接入自动战绩记录，不替换当前已经可用的 WPF 版本。

## 在游戏电脑检查

可以安装 Setup，或完整解压便携 ZIP 后打开 `BetterApex-Rust-Lab.exe`。便携包里的 `resources` 文件夹必须与程序一起保留。

1. 检查程序是否能启动，页面是否清楚、文字是否正常。这个版本只有一个主窗口，左侧是本阶段三个验证项目。
2. 在“画面采集”选择 Apex，点击“开始采集验证”后切回游戏。常规最多每 2 秒取一次图，切出后暂停。返回工具时可展开预览查看最近一次有效画面，也可停止采集后保存原始 PNG。用于显示和保存的旧画面不会作为新帧重复处理。
3. 在“识别通路”选择一张完整的 16:9 结算图，验证三人的伤害区域；也可选择局内图验证昵称区域。此处没有迁移完整 KDA 解析、昵称后处理、匹配和保存功能，不能按正式版使用。
4. 在“旧数据读取”选择旧版的 `data/matches.db`，建议先复制完整旧数据目录再选副本。查看最近最多 50 场、三人数据和身份状态。数据库以只读方式打开，不升级、插入或修改记录。

测试后继续用旧版进行正式自动记录。两个版本的用途不同，迁移原型不会自动接管旧版任务。

## 运行条件

- Windows x64，目标为现有 Windows 10 游戏电脑，开发端目前在 Windows 11（内核版本 10.0.26200）完成基础验证。Windows 10 实机兼容性仍由此次测试确认。
- 使用电脑已有的 WebView2 Runtime。Setup 会检查并在需要时引导补装；本包不捆绑整套固定版本浏览器环境。
- Windows OCR 需要简体中文识别组件，Tesseract 沿用旧版 x64 原生 DLL 与模型，因此仍需其原生运行库依赖。缺失时界面返回原因。
- 用户电脑不需要安装 Rust、Node.js、.NET SDK，也没有 C# 后台进程。

## 体积说明

本阶段 Setup 实测约 19.53 MiB；便携应用目录约 35.25 MiB（压缩前，附加说明文件前）。包含现有中英文模型、x64 OCR 库和许可说明，不含完整 WebView2、Windows 语言组件及额外系统运行库。

Setup 由当前开发配置构建，另外附带开发用命令行验证器和卸载程序；便携包仅提供图形程序与资源。后续正式发布会统一产物范围。

最终 ZIP 大小以同目录发布信息为准。完整功能迁移后的体积和游戏性能还需重新测量，不能将本原型数据当作最终版承诺。

## 本轮反馈重点

检查能否启动、是否无黄框取得完整游戏画面、能否运行 OCR、能否看到旧数据库内容即可。记录出错页面和文字；不要求为本阶段补齐更多对局样本。
