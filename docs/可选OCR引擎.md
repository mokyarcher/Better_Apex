# 可选昵称 OCR 引擎

## PP-OCR结算数字与未完成结算的新局切换（2026-11-01）

当前选择PP-OCRv6 small时，排名、小队总击杀、三人击杀／助攻／击倒／伤害及结算卡片匹配线索均由同一PP-OCR实例识别，不混用旧数字引擎。数字按现有ROI与前景完整字形界限直接送识别模型，省去数字文字检测；保留位数、格式、前导零、置信度和跨帧一致性校验。原Windows OCR＋Tesseract选项保留为明确可选路径；配置字段nickname_backend兼容旧设置文件，现在同时决定昵称与结算数字引擎。

自动复核只读取两帧数字，稳定后在最新结算证据帧读取一次三张卡片线索；数字重试不反复读取昵称卡片，没有可靠02名单时也不读取无用线索。匹配线索读取失败不会阻止已确认数字保存，失败卡片身份保留未知并写日志。最终自动昵称仍只能来自同局02单次名单，03文字不能直接提供最终昵称。

修复未保存结算时不再检查新局入口的问题：看到03后，即使尚未保存，也继续检测00／01。发现新一局加载或选传奇时，结束旧等待、清空旧名单并恢复2秒节奏，仍需新02两帧确认。不将未知数字编造成战绩，不将旧名单带入下一局；日志记录unresolved_settlement_left及最后解析结果。本次反馈原JPEG保存在image_for_test/异常识别问题2-结算后进入下一局.jpg，按原文件哈希核对，作为加载页与合成未完成状态上下文的回归；它不是上一局结算数字的证据。

验证：40项Rust、3项前端测试通过。14张结算图×14字段，PP及原引擎各196字段全部符合人工真值；另有74／665／117反馈图与下一局加载回归。Debug双引擎完整单图均值约PP1591ms／原引擎520ms，包含不同昵称通路，不能据此宣称数字单项耗时或实战精度／FPS提升；单张反馈图的数字独立328ms、一次卡片线索1151ms仅为开发机样本。报告在.local/ppocr-settlement-review/comparison.json与feedback.json，测试不写正式战绩。

## 使用与作用范围

设置 → OCR 引擎 → 昵称识别版本，可选择 **PP-OCRv6 small** 或原 **Windows OCR + Tesseract**，点击“保存 OCR 设置”。没有设置文件时默认试用 PP-OCRv6 small；用户保存后以数据目录 `ocr-settings.json` 为准，重启保留。损坏设置会显示错误并临时使用原引擎，不覆盖损坏文件，重新选择保存可恢复。

切换前必须停止自动记录；后端在 worker 锁内再次检查，不能靠其他入口绕过。加载成功后才保存设置，模型缺失／加载失败不覆盖原选项，也不静默回退。切换会清空尚未保存的手动识别结果和暂存名单，请先保存需要的记录。已保存战绩不修改。

本次替换的是昵称文字后端：01 左上／底部、02 HUD、03 卡片匹配线索、相应手动识别与保存重识别。原引擎在 01 仍融合 Windows／Tesseract 两个读数，在 02／03 使用 Windows；新引擎在每块 ROI 内检测水平文字行并用 small 识别模型解码。沿用原 ROI 和 3 倍裁图，未新增全屏文字识别。

00→01→02→03 页面判定、对局标记、战绩数字读取、采样预算、投票阈值、跨阶段一对一匹配、下一局隔离及去重全部沿用现有机制。**03 文字永远只是不可信匹配线索，不能成为最终昵称或投票来源。** 原始引擎名、文字行／置信度／裁图内边界、区域耗时、空结果与错误继续写入临时 TXT／JSONL 日志；一帧一区域仍只贡献一票，不把每条文字行重复计票。

当前已知的“02 先投票通过才能合并 01”限制及不稳定区域稀释有效票的问题，本次按用户要求保留原机制，没有通过降低阈值或猜测昵称绕过。更换引擎不能保证所有“归属待核对”消失。

## 本地运行与资源

Rust 使用 ort 2.0.0-rc.12 动态加载随包附带的 ONNX Runtime 1.24.4 Windows x64 CPU 运行库。检测／识别各单线程，关闭线程自旋和并行执行；自动线程仍为较低优先级。每个自动 worker 只加载一次模型，在 01／02／03 复用；没有并行运行两套昵称引擎、补赶采样、Python 进程、云端 OCR 或 GPU 依赖。页面判定仍需要 Windows 简体中文 OCR。

新资源位于 `rust-app/src-tauri/resources/ppocr-v6-small/`，交付必须与完整 resources 一起复制。包含两个 ONNX 模型、运行库、上游许可及 `manifest.json`。模型启动时校验固定 SHA-256；部署脚本同时校验运行库和许可。不能只替换旧 EXE 而不带新资源。

- [PaddleOCR 模型说明](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv6/PP-OCRv6.en.md)
- [RapidOCR 模型清单](https://github.com/RapidAI/RapidOCR/blob/main/python/rapidocr/default_models.yaml)，使用 v3.10.0 目录的 small ONNX 模型和内嵌字符表。
- [Microsoft.ML.OnnxRuntime 1.24.4](https://www.nuget.org/packages/Microsoft.ML.OnnxRuntime/1.24.4)

开发机准备：`./scripts/Prepare-PpOcr.ps1` 仅离线检查／从已有校验通过的缓存解出资源；干净检出缺少文件时显式加 `-DownloadMissing`，下载后核对 `scripts/ppocr-assets.json` 中固定哈希。资源目录仍不纳入源码管理。`Publish-RustPortable.ps1` 构建前先做离线校验，不会发布缺新模型的程序。
