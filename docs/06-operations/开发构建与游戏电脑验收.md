# 开发、构建与游戏电脑验收

状态：现行　更新：2026-11-02

## 开发环境

Windows x64、Rust MSVC工具链、Visual Studio C++构建工具和Windows SDK、Node.js、WebView2。依赖版本由 Rust/npm 锁文件约束。

首次准备：

```powershell
cd rust-app
npm ci
cd ..
./scripts/Prepare-RustResources.ps1
./scripts/Prepare-PpOcr.ps1 -DownloadMissing
```

`Prepare-RustResources.ps1` 复制仓库里的Tesseract字库/许可，并从 `.local/packages/tesseract/5.2.0/x64/` 取原生DLL；缺少DLL时需恢复对应NuGet包。PP-OCR脚本默认检查本地模型，需要下载时才加 `-DownloadMissing`。生成的Tauri资源位于 `rust-app/src-tauri/resources/`，不纳入源码管理。

开发模式：

```powershell
$env:CARGO_TARGET_DIR = Join-Path $PWD '.local/rust-target-gui'
cd rust-app
npm run tauri dev
```

## 正式构建与交付

统一使用项目根目录 `scripts/Publish-RustPortable.ps1`。发布脚本会检查PP-OCR资源，但**不会自动运行** `Prepare-RustResources.ps1`；干净检出或Tesseract资源缺失时，先完成上方资源准备。随后脚本执行带 `custom-protocol` 的Tauri正式构建，并将EXE与完整资源复制到：

```text
.local/BetterApex-Rust-AutoRecord/BetterApex-Rust-AutoRecord.exe
.local/BetterApex-Rust-AutoRecord/resources/
```

直接运行/复制时EXE与同目录完整 `resources/` 必须一起保留。正式程序不要求目标机器安装Rust、Node.js或Python。不默认生成Setup/ZIP，不自动启动桌面程序做验收。普通 `cargo --release` 不是正式Tauri发布替代方案。

## 游戏电脑检查

开发和编译在开发电脑；工具与Apex需在游戏电脑同机运行。用户选择测试时：

1. 复制完整的 `BetterApex-Rust-AutoRecord/` 文件夹，确认 `resources/` 齐全，再启动EXE。
2. 选择Apex窗口，主动开始自动记录；观察00→01→02→03状态和本地历史是否对应实际流程。
3. 检查一场保存后只出现一条记录，切到工具再回游戏不会重复或错接名单。
4. 若检查自动下一局，确认开关开启后正常完成一局；观察是否只发送一次数字1及Apex是否真的显示匹配。可先关闭设置避免自动输入。
5. 如检查浮窗，记录窗口化/无边框/独占全屏、分辨率、缩放和HDR条件；不可把开发机预览结果当作游戏内覆盖证明。
6. 记录软件版本、游戏版本、显示模式、发生时间、页面状态和错误文字。昵称问题提供该次运行对应TXT/JSONL；先由用户检查日志内容再选择是否分享。

实测结论只适用于记录的设备和设置。新自动下一局的真实按键接收尚未验证；无需为一次回归反复玩多局，按遇到的问题做最小复现。

## 数据和诊断

新版SQLite、证据图、OCR/浮窗设置和 `nickname-debug/` 位于Tauri应用本地数据目录（应用标识 `local.betterapex.rustlab`）。仓库根目录 `data/` 是旧数据，不是新版位置。调试日志可能包含玩家昵称；不上传、不覆盖、不自动清理，报告问题时仅提供必要文件。
