# OCR 识别规范

状态：现行　更新：2026-11-02

## 引擎选择与范围

设置页可选 **PP-OCRv6 small** 或 **Windows OCR + Tesseract**。无用户保存设置时采用PP试用默认；选择持久化在新版数据目录 `ocr-settings.json`。设置文件损坏或无法读取时，显示错误并临时采用 Windows OCR + Tesseract，不覆盖原文件；用户重新选择并成功保存后清除错误。自动记录运行中不能切换；切换前必须停止，后端再次校验。一个worker固定使用一个昵称/结算引擎，不静默回退或在同一局混合来源。

切换引擎会清空尚未保存的手动识别结果和暂存名单；需要保留时先保存或记录，再切换。

`nickname_backend` 是兼容字段，目前同时决定昵称与结算数字引擎。00→01→02→03页面判定、采样节奏和身份来源规则不由引擎切换改变。自动昵称只在02 HUD确认后读取一次；03卡片文字只提供粗匹配线索。详细关联规则见[自动记录流程规范](自动记录流程.md)。

## 引擎执行

- **PP-OCRv6 small**：Windows x64 本地 ONNX Runtime 1.24.4 CPU 单线程运行。昵称ROI内做水平文字检测和CTC识别；结算数字用现有ROI/可见字形边界送同一PP实例，不混用旧数字引擎。页面判定和对局标记仍走既有Windows机制。
- **Windows OCR + Tesseract**：保留原本地识别路径。简体中文页面判定使用Windows OCR；Tesseract语言模型在仓库 `assets/tesseract/tessdata/`，原生DLL由 `scripts/Prepare-RustResources.ps1` 从开发机NuGet缓存复制进交付资源。
- 两种方案均使用固定小区域，不执行全屏通用文字识别、不启动Python、不依赖GPU或远端OCR。

## 设置错误和识别失败

- 模型缺失或固定SHA-256校验失败时显式报错；发布资源缺失不得产出不完整交付。
- 切换时先成功加载新引擎，再保存设置；失败不静默更换引擎，不覆盖原设置。
- 空昵称、OCR错误、歧义身份保留未知；不使用03昵称兜底。未知数字与真实0分开存储。
- 结算数字跨帧确认、伤害追加新帧及卡片线索读取时机以自动流程规范为准。

## 资源准备与发布

模型来源、许可和固定哈希由 `scripts/ppocr-assets.json` 管理。`scripts/Prepare-PpOcr.ps1` 默认只校验/使用已有缓存；干净检出缺模型时显式传 `-DownloadMissing` 并核对哈希。资源目录 `rust-app/src-tauri/resources/` 不入 Git，正式包必须完整携带。Tesseract许可随语言资源保留。

引擎对比只说明固定样本上的差异。当前14张结算图、每张14个数字字段的回归不能证明总体准确率；Debug单次计时不能证明Release耗时、游戏帧率或实战性能。结果和证据层级见[验证策略与结果](../05-quality/验证策略与结果.md)。
