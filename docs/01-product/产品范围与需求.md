# 产品范围与需求

状态：现行基线　更新：2026-11-02

## 产品目标

Better Apex 是面向 Apex Legends 玩家、运行在 Windows 桌面上的本地战绩工具。它读取用户屏幕上可见的游戏画面，识别结算数据并保存在本机，让用户能回看单场战绩和来源证据。

核心目标是让自动记录在可识别时可靠保存；无法确认的数字或玩家身份保持未知，不能靠猜测补齐。

## 当前用户流程

1. 用户启动工具，选择 Apex 窗口并主动开始自动记录。
2. 工具按低频采集和页面状态识别流程跟踪加载、选传奇、对局和结算。
3. 结算数据经校验后自动写入本机数据库；昵称只在证据足够时关联。
4. 用户查看历史、结算截图和必要的局内昵称证据，也可导入截图手动补录。
5. 完整数字的新自动保存成功后，可按设置执行一次受约束的下一局操作。

具体流程规则见[自动记录流程](../04-specs/自动记录流程.md)。

## 当前范围

- Windows x64 桌面应用；Rust + Tauri 2 + Vue 3。
- 低频窗口采集、00→01→02→03 自动记录、手动截图识别、本机 SQLite 历史和来源截图。
- 可选择 PP-OCRv6 small 或 Windows OCR + Tesseract；支持记录状态浮窗、托盘和单实例。
- 排名、小队总击杀及三名玩家的击杀、助攻、击倒、伤害按当前界面和校验规则记录；未知值与真实 0 分开。
- 用户可关闭自动下一局；此功能的约束见流程规范。

## 明确非目标

- 不读取/注入游戏进程、不修改游戏文件、不读取游戏内存；不录制整局视频。
- 不上传战绩、截图或调试日志，不要求游戏账号登录；没有云同步、排行榜或跨设备服务。
- 不导入、迁移或合并旧 WPF 版战绩。自动下一局只属于明确定义的单次操作，不扩展为通用游戏自动化。
- 不承诺覆盖所有语言、分辨率、显示模式、赛季界面或玩家场次；支持边界以实测证据为准。

## 数据和信任原则

- 缺失/冲突的字段保存为空或待核对，不补 0；来源和身份未确认时不伪装为已确认。
- 数字结果与昵称身份分开确认。结算卡片昵称只作为匹配线索，自动保存的昵称必须来自本局 HUD 名单。
- 本地数据库、配置、截图和临时调试日志均留在用户设备；两代程序数据互不读写。
- “已记录的对局”不代表账号完整生涯数据；小样本回归不能转换成总体准确率或实战覆盖率承诺。

## 验收原则

产品行为通过自动化测试和可复现样本检查；实机采集时序、Apex 对输入的响应、不同显示模式下的浮窗和游戏性能必须单独记录为游戏电脑验收结果。没有该证据时标为“待实测”，不以编译或截图回归替代。
