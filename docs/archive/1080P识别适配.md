## 此前实现

- 继续按实际游戏客户区尺寸采集，以画面宽高比例裁剪阶段提示、02昵称和结算区域。没有把整帧1080P放大成2K；证据截图仍保持实际输入尺寸。
- PP-OCRv6 small的昵称通路无需改模型或ROI：六张1080P局内图的18个昵称候选，与此前六张2K原图的候选逐字一致。这里比较的是两次OCR输出，不是账号信息核实后的总体准确率。
- 修复1080P小字号排名：反馈图中的第9名原来读成第5名。小字号排名使用黄色文字前景掩码，剔除红色／动态背景；去掉“第”字后的单个数字使用Tesseract单字符模式，多个数字仍按数字串识别。1080P排名低置信度结果保留未知，不作为确定排名保存。较大分辨率继续使用原已校准的排名预处理与判断规则，避免影响原2276×1280反馈图及2K基线。
- KDA、伤害、小队总击杀、02五次投票、首次候选平票决胜、03不得提供最终昵称、新局隔离与去重规则不变。01仍只监视流程，不解析昵称。
- 开发CLI基线入口自动查找相同主干的JPG／PNG／JPEG／BMP，支持直接使用1080p派生目录；不再在普通基线回归中识别01昵称。
- 设置页“采集与运行”显示“画面分辨率：1080P / 2K”，说明完整16:9画面自动适配。

## 开发验证入口

在项目根目录执行：

```powershell
$env:CARGO_TARGET_DIR = Join-Path $PWD '.local/rust-target-gui'
cargo test --manifest-path rust-app/src-tauri/Cargo.toml --lib --offline
cargo run --manifest-path rust-app/src-tauri/Cargo.toml --no-default-features --bin compatibility-cli --offline -- image_for_test/1080p
```
