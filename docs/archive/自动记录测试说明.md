# Rust 自动记录测试版使用说明

## 保存后自动下一局（2026-11-01）

按用户明确要求新增：自动记录取得完整结算数字并成功新建战绩后，可向选定游戏按一次主键盘数字1继续下一局。设置页默认开启，可随时关闭，写入新版数据目录auto-next-settings.json，重启保留；设置损坏时关闭此功能并提示。

触发条件：排名、小队总击杀、三人K/A/击倒/伤害均有效；数据库事务已成功；不是去重命中；随后取得另一张新结算帧，画面仍新鲜（1.5秒内）、标题仍为结算，右上存在可用重新匹配提示且没有取消／匹配中／正在等排队状态。不会额外截图或提高常规频率，仅对单次待执行动作追加小区域确认。

按键前再次检查选定窗口句柄／PID、前台、非最小化、停止标记、功能开关及Ctrl／Alt／Shift／Win／数字1是否按住；不切换或抢夺焦点。发送扫描码0x02按下、50ms后释放，仅一次，失败不重新按下。状态及浮窗区分已发送数字1与已进入匹配，不假装游戏已接收。

切出游戏、关闭开关、停止记录、离开本局结算，或10秒内没有新的确认画面，取消本次动作，不在用户返回后补按。手动导入保存、pending历史恢复、去重保存与含未知数字的记录不触发。新局仍按00／01→新02连续确认推进，不跳过既有名单隔离与保存锁。日志新增auto_next_cancelled／auto_next_result事件，不记录用户键盘内容，不修改旧战绩。

## 启动方式

从开发目录复制新版 BetterApex-Rust-AutoRecord 文件夹到运行 Apex 的电脑，双击其中的 EXE。EXE 需要同目录 resources 文件夹；请一起复制。无需解压 ZIP，也不需要在游戏电脑安装 Rust 或 Node.js。新版数据与旧 WPF 版分开保存。

## 自动记录流程

1. 打开程序进入“自动记录”，选择 Apex 窗口并点击“开始自动记录”，然后切回游戏。
2. 左上出现“三人赛”时进入加载；出现“小队静音”和“选择成为跳伞指挥官”时只显示选传奇阶段，不解析昵称。
3. 连续两帧确认局内HUD后，只在确认帧读取一次左下三人昵称，各槽位直接采用这次结果，不计票、不重试。空结果或错误占用唯一一次尝试并保留未知；切出恢复不重新读取，新一局才重置。02保持常规2秒采集，只有结算确认临时改为1秒。
4. 对局结束进入显示“小队排名”和“小队总击杀”的结算页后，采集间隔临时变为 1 秒。连续读数有效且一致时，识别玩家数据、关联昵称并自动保存。
5. 保存后停留在结算页不会重复写入。程序看到下一轮的加载/选传奇画面后，会等待新局 HUD 连续确认，再开始下一条记录。

首次启动时若已经在对局中，程序可通过两帧局内 HUD 开始记录；若启动时已经处于结算页，程序不会把它当成刚观察完整的一局自动保存。

## 采集节奏与状态

- 常规每 2 秒最多采集 1 帧。
- 01仅监视阶段，02只识别一次三人昵称，均保持2秒采集；只有结算确认临时提速至1秒。
- 切换到工具窗口、游戏最小化或关键区域被遮挡时，DXGI 会暂停采集；画面恢复后继续处理。
- 长时间没有新画面时，单独显示暂停原因并保留本局进度；不会仅因 20 秒未取得新帧而清空一局。结算恢复后重新确认两帧，已保存的同一局仍不会重复保存。中断后身份连续性不明时，不带入旧名单，本人归属保留待核对。
- 游戏性能和不同窗口模式需在游戏电脑实际确认。采集/OCR 低优先级执行，不做全程录像。

## 记录和核对

- 03 结算页的排名与小队击杀需要稳定识别，未稳定时会继续按 1 秒间隔检查。
- 最终自动昵称只来自同局02单次识别名单；03只作不可信的一对一匹配线索，不能补名。存储字段`voted_roster`保留为兼容标签，当前表示02自动名单，不代表执行了投票。
- 名单不完整时不会沿用上一局名称。连续停留同一结算页不会增加记录。
- 结算图和一个可用的昵称来源图保存在本地历史记录中；本地数据库与证据图片均不上传。
- 自动保存后，最近一场、历史列表和记录数量自动更新，无需手动刷新；正在查看旧战绩时保留详情，可点击“查看新记录”打开新保存的一局。收至托盘后恢复窗口会补读状态和历史。

## 临时昵称复盘日志

当前调试版启动后默认记录昵称样本，不必另行打开。进入“设置 → 临时昵称调试日志 → 打开日志文件夹”：

- 同名前缀 `.txt` 适合直接阅读，`.jsonl` 适合后续分析；每次运行新建一组文件，按北京时间、局编号、阶段及采样序号查找。
- 调试日志继续默认开启，round_started记录hud_frames=1、recognition_rule=single_read_no_vote；hud_result记录单次原文、三人结果、attempts=1及sampling_complete=true。空结果／错误记录后不重试，不删除旧日志。
- 可以在设置页关闭本次运行的记录，已有文件保留。重启当前调试版会默认开启；不会自动删除旧日志。
- 复盘时可直接打开 TXT；需要定位问题时提供对应同名前缀的一组文件即可。日志只在本机，不自动上传；此前旧版本未记录的样本不能补回。

## 切换昵称 OCR 版本

进入“设置 → OCR 引擎 → 昵称识别版本”，可选择 PP-OCRv6 small 或 Windows OCR + Tesseract，点击“保存 OCR 设置”。没有已保存设置时默认试用新模型；选择会在重启后保留。请先停止自动记录再切换；切换会清空尚未保存的手动识别结果和暂存名单，请先保存需要的记录。

两种昵称引擎都使用局内单次读取规则。页面判定、数字读取保持原样；已保存记录不修改。最终自动昵称只来自同局02单次识别名单；03只作不可信的一对一匹配线索，不能补名。存储字段`voted_roster`保留为兼容标签，当前表示02自动名单，不代表执行了投票。

复制本次可运行版时必须一起复制完整 resources 目录，其中新增 ppocr-v6-small；游戏电脑无需 Python 或联网。若模型资源报错，可检查目录或切回原方案，不会自动混用引擎。实机只需正常完成一局，若昵称仍不对或出现卡顿，请提供对应 TXT／JSONL、大致时间、当前所选引擎；有卡顿时可停止后切回原方案。有限对比详见 [可选 OCR 引擎](可选OCR引擎.md)。
昵称来源图只保存一张02 HUD，文件名仍含selection以兼容旧库。日志保留单次调用、空结果／错误及最终关联，没有投票过程。
