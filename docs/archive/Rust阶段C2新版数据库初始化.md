# Rust 阶段 C2：新版本地战绩保存与历史

日期：2026-10-31；版本：0.2.0。

## 范围

新版现在可初始化独立 SQLite 数据库，将结算识别结果保存为本地战绩，在历史页查看列表、数值、昵称确认状态和来源截图。手动保存和阶段 D 自动记录共用存储层；自动记录先持久化待保存任务，再进行幂等写入与恢复。新版不搜索、打开或导入旧版战绩。

## 数据位置与结构

Windows 版使用 Tauri `app_local_data_dir()`，数据库文件为该目录下的 `matches.db`，应用标识为 `local.betterapex.rustlab`。原始截图副本保存在同目录下的 `evidence/`，数据库仅保存相对路径。原始输入图不会被修改；后续移动或删除导入文件不影响已存战绩。

Schema v1 包含 `matches`、`players` 和 `match_images`。SQLite `application_id` 与 `user_version` 用于识别数据库及其结构版本；遇到其他应用数据库、未知表结构或更高版本时拒绝修改。保存战绩、玩家和来源图路径在一个事务中提交；截图以 SHA-256 作为对局记录 ID，重复保存同一结算原图会打开既有记录并更新可补充的字段。

未识别的数字用 SQL `NULL` 保存，和真实 0 区分；昵称是否已核对、本人身份均单独存储，未确认时保持待核对。每场记录保存结算原图；若关联了局内昵称截图，也会一并保存并在历史详情中查看。

## 使用流程

1. 在“手动导入”选择完整结算截图并识别。
2. 检查排名、队伍击杀及三名玩家数字。可修正昵称、勾选已核对、选择本人位置；不确定的项目留空即可。
3. 若已识别本场选传奇界面，可先暂存名单，再导入同一局结算图，从列表中为每个结算位置选择对应队员。暂存只保留在当前应用内存中；关闭或重启应用后需重新读取昵称图。
4. 点击保存后，在“战绩记录”查看本地记录和来源截图。

匹配由用户逐位置选择，没有自动相似度或本人推断。未勾选“已核对”的名称仍标记为待核对。保存不上传云端。

## 本机验证

已通过前端生产构建和 Rust 存储定向测试。测试覆盖空库初始化、记录与三名玩家保存、未知与 0、昵称/本人标记、结算与昵称来源截图副本、重复保存去重，以及使用新 03 结算原图识别并保存排名 12、小队击杀 2、伤害 174/158/321。测试使用 `.local/storage-tests/` 临时目录，不写入正式用户数据库。

游戏电脑上的实际截图导入、昵称人工关联和界面使用仍需在用户机器验收；这不影响本地编译和存储单元测试结果。
