## 自动流程

1. **00 加载中**：监测左上角“三人赛”标题。它只表示新一局加载阶段，不开始收集名字或保存战绩。
2. **01 选传奇**：识别两个操作提示，仅更新阶段与新局边界，保持2秒，不读取昵称。
3. **02 对局中**：连续两帧确认局内HUD后，只在确认帧读取一次左下三人昵称，各槽位直接采用这次结果，不计票、不重试。空结果或错误占用唯一一次尝试并保留未知；切出恢复不重新读取，新一局才重置。02保持常规2秒采集，只有结算确认临时改为1秒。
4. **03 结算**：检测右上“小队排名”和“小队总击杀”标题。找到第一帧结算候选后，将采集间隔临时提升为 1 秒；下一帧开始核对排名、总击杀及三人数据。若还未稳定，后续每秒只重新识别新帧，并与上一次结果比较。
5. **保存**：排名与小队击杀有效且连续一致后保存三人数据和证据图。自动昵称只来自同局 02 单次识别名单；03 的 `nickname_hint` 仅用于卡片一对一对齐，不参与投票，不得用于展示或存储昵称兜底。对应可靠时保存名单原文，模糊关联标记归属待核对；对应失败时仍存数值，身份为空。
6. **下一局**：停留在结算页不会重复入库。结束后检测到新一轮 00 或 01 画面才准备清空旧名单；仍需连续确认新 02 HUD，才解除上一局锁定并开始新一局记录。

如果工具启动时已经处于对局中，仍可通过连续两帧 02 HUD 进入本局记录；若启动时已处于结算页，由于没有观察到本局的入局状态，不会直接创建战绩。

## 结算停留时回退／漏记修复

用户反馈在结算页停留时，界面出现“等待有效局内画面，恢复后重新采集名单”并高亮局内阶段，且已有一次未正确记录。排查发现该文字来自无新采集帧超过 20 秒的分支：旧实现会清空本局 `active` 和名单，恢复到结算页时又因未观察入局而拒绝自动保存。前端还会根据提示文字中的“局内／名单”推断阶段，形成误导显示。静态桌面、切出或 DXGI 中断都可能造成无新帧，截图本身不能确认当时停止取帧的具体原因。

现已将采集暂停与对局阶段分离：

- 超时仅设置 `pause_reason`，保留阶段、入局资格、昵称证据和保存锁；恢复后重新核对两张新结算帧。
- 已看到结算后，忽略把本局倒退成局内的孤立 HUD 判定；没有新局入场证据时，即使连续出现不同 OCR 对局标记也不解除保存锁。
- 长时间中断后，只有已知对局标记重新匹配才复用旧昵称证据；已知冲突仍拒绝混用，连续性未知时可保存当前结算数值，但不沿用旧昵称或本人身份。
- UI 使用 Rust 提供的 `stage` 枚举更新进度，暂停原因单独展示，不再解析人类提示文字。
