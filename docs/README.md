# 开发文档目录与维护规范

更新日期：2026-11-02。本文规定项目文档的分类、权威来源和更新方式。当前产品由 Rust + Tauri + Vue 实现；进行中的开发以代码、现行规范和进度文档为准。

## 文档结构

| 路径 | 文档职责 | 必须包含的信息 |
| --- | --- | --- |
| `../README.md` | 项目首页 | 一句话定位、当前能力概览、文档入口；不放实现细节和历史周报 |
| `../agent.md` | AI/协作者工作约定 | 项目入口、代码修改规则、验证边界、文档维护规则；不复制完整功能规格 |
| `01-product/产品范围与需求.md` | 产品需求基线 | 用户问题、当前目标、范围/非目标、数据与隐私约束、验收标准 |
| `02-architecture/系统架构与决策.md` | 系统设计 | 模块职责、数据流、存储/资源边界、关键技术决策及原因 |
| `03-planning/开发计划与进度.md` | 当前计划和状态 | 已完成、待验证、明确阻塞、下一步；每项注明证据或验收条件 |
| `04-specs/自动记录流程.md` | 自动流程行为契约 | 阶段、触发条件、采样、状态转换、身份/保存/异常规则 |
| `04-specs/OCR识别.md` | OCR 行为和资源规范 | 引擎选择、输入/输出、校验、失败处理、模型与部署要求 |
| `04-specs/游戏状态浮窗.md` | 浮窗功能规范 | 指标定义、显隐、交互、设置持久化、已知兼容边界 |
| `05-quality/验证策略与结果.md` | 验证方法与现有证据 | 命令、环境、样本范围、结果、限制；测试结论不外推 |
| `06-operations/开发构建与游戏电脑验收.md` | 开发、构建、交付和实机检查 | 环境准备、命令、产物路径、资源清单、用户检查步骤和反馈要求 |
| `archive/` | 阶段记录和已废弃方案 | 保留历史上下文，标记“仅历史，不是当前规范” |

## 权威顺序

1. **代码是已实现行为的最终事实来源**；当前文档说明希望维持的产品行为和约束。
2. 需求边界以产品范围文档为准；模块和数据边界以架构文档为准；用户可见行为以对应功能规范为准。
3. 当前状态只写在开发计划与进度文档；验证数字和样本只写在验证文档；命令与运行路径只写在运维文档。
4. `archive/` 内文件只说明当时做过什么，不能覆盖上面现行文档。阶段文档中的旧规则、旧测试计数、旧路径不得当作当前事实。

## 更新规则

- 一个现行事实只维护在一个权威位置，其他文档用链接引用，不复制长段落。
- 修改用户流程或状态机时，同步更新 `04-specs/自动记录流程.md`；调整 OCR、浮窗时更新各自规范；技术边界改变时更新架构文档。
- 里程碑完成或出现实际阻塞时更新进度文档，不把每次提交写成周报。验证结果只在验证文档新增简短记录，并注明样本、环境和未覆盖范围。
- 构建/安装/运行步骤变化时更新运维文档。README 保持为导航页；协作者规则变化才更新 `agent.md`。
- 新需求先写明目标和可验收结果，再进入开发计划；暂未确认的想法标“候选”，不写成承诺。
- 重要文档顶部注明 `状态：现行 / 提案 / 历史` 与更新日期。废弃文档移至 `archive/`，并在归档索引写明替代文档。

## 标准内容模板

**需求**：目标与用户 → 范围/非目标 → 规则和数据边界 → 可观察验收条件。避免先写实现方案替代用户需求。

**架构/决策**：上下游和模块职责 → 数据流/生命周期 → 约束与失败边界 → 决策及理由/代价。重大、独立决策可另建 ADR，需包含状态、背景、决定、后果。

**功能规范**：状态/触发 → 正常路径 → 失败与取消 → 持久化和副作用 → UI/日志 → 验收条件。区分“必须”与“当前实现”。

**计划与进度**：目标 → 当前阶段 → 状态表（完成/进行中/待外部验证/暂缓）→ 下一步和退出条件 → 风险。只列已确认工作，不填虚构工期。

**验证记录**：提交/版本 → 环境与命令 → 样本和预期 → 结果 → 限制/未验证项。静态样本、编译通过、桌面启动、真实游戏实测是不同级别的证据。
