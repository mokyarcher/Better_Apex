# Better Apex

Apex 玩家的本地战绩工具。当前主程序使用 **Rust + Tauri 2 + Vue 3**，通过低频 DXGI 采集与本地 OCR 自动记录结算，保存到独立 SQLite 和来源截图目录；不上传云端，不读取游戏内存，不导入旧 WPF 数据。

更新日期：2026-11-01。用户反馈：此前版本经过长时间实际游戏测试，暂未发现问题。新增“保存后自动下一局”已完成代码、回归和正式构建，实际游戏按键接收效果尚待用户确认；不将此前稳定性反馈视为新功能已验收。

## 当前功能

- **自动记录**：00 加载 → 01 选传奇 → 02 局内 → 03 结算 → 本地历史。常规每2秒最多一帧，结算确认临时每秒最多一帧；切出或最小化暂停，恢复后继续本局，结算停留不重复保存。
- **局内昵称**：01只监视阶段；02连续两帧确认HUD后仅读取一次三人昵称，不投票、不重试，空结果保留未知。最终自动昵称只来自同局02名单，03卡片文字只用于一对一匹配，不能补名或兜底保存。
- **结算识别**：选择PP-OCRv6 small时，排名、小队总击杀、三人击杀／助攻／击倒／伤害及卡片匹配线索使用同一PP实例。自动复核两帧只读数字，确认后才读取一次卡片线索；原Windows OCR + Tesseract仍可选。切换引擎前需停止自动记录，设置重启保留。
- **识别失败处理**：未知数字不填0。伤害未知或冲突时最多追加3张新结算帧；未完成结算也继续检测下一局00／01，避免停留在旧03，且不沿用上一局名单。支持完整16:9的1080P／2K输入，无需手动切换分辨率。
- **自动下一局（默认开启）**：完整结算数字自动保存成功后，再确认一张新鲜结算帧和可用的重新匹配提示，每局最多按一次主键盘数字`1`。设置中可关闭；切出、停止、关闭开关、画面变化、修饰键按住或确认超时则跳过，不补按。手动保存、历史恢复、去重和含未知数字的战绩不会触发。
- **游戏状态浮窗 Display**：可选开启，显示记录阶段、暂停／重试／按键结果、软件自身CPU与专用内存；包含WebView2子进程，每2秒采样。支持上／下居中、不透明度、鼠标穿透和15秒预览，切出游戏隐藏。内存目前统计专用提交量，与任务管理器默认工作集口径不同；尚未改成工作集。适用于窗口化／无边框，独占全屏可见性不作保证。
- **历史与手动补录**：自动保存后刷新历史、数量和最近一场，查看旧详情时保留选中项；支持手动截图识别、人工关联与保存。未知身份保留待核对，证据图随记录保存在本地。
- **后台运行**：单主窗口、托盘与单实例。自动记录运行中关闭主窗口会收至托盘；托盘可打开窗口或退出。
- **临时调试日志**：每次运行默认开启，在新版数据目录`nickname-debug/`生成TXT＋JSONL，记录实际OCR、空结果／错误、数字与昵称关联、保存及自动下一局结果；不覆盖、不自动清理、不上传，也不额外保存逐帧截图。

## 运行与交付

当前直接运行版：

```text
D:\GitCode\myproject-d\Better_Apex\.local\BetterApex-Rust-AutoRecord\BetterApex-Rust-AutoRecord.exe
```

复制EXE时必须一起复制同目录完整的`resources/`，包含PP-OCR模型、运行库和许可。游戏电脑无需安装Rust、Node.js或Python。旧Setup不会自动随直接运行版更新；只有明确要求时才重新生成Setup或ZIP。

正式构建使用项目根目录的`scripts/Publish-RustPortable.ps1`，自动构建前端，以Tauri `custom-protocol`嵌入页面。普通`cargo build --release`不能替代正式发布。

## 旧 WPF 版本功能与原图回归

以下图片导入、旧版数据目录、`.NET` 启动和测试说明描述的是旧 WPF 版。新版 Rust/Tauri 的编译和测试入口见 [Rust 项目说明](rust-app/README.md)，新版不读取旧数据。

历史 WPF 原图样本已由用户移除，不再作为当前测试依据。image_for_test 根目录保留新的 00、01、02、03 四张基线原图；regressions 子目录另存本次第 9 名／5 击杀结算反馈附件，适用于 Rust 自动记录流程回归。
- 选择本地 PNG、JPG/JPEG、BMP 图片，等比例预览。
- 显示文件名、原始分辨率和文件大小。
- 支持替换、清除预览，取消选择时保留原预览。
- 损坏或无法读取的图片显示错误，已有预览不丢失。
- 图片仅在本机读取，不上传，不修改源文件。
- 点击“识别战绩”，在本机识别左、中、右三名玩家的昵称候选、击杀/助攻/击倒、伤害及小队排名和总击杀。
- 战绩卡片只展示最终数据，无法确认的字段显示“待核对”，不补成 0；不展示原始 OCR 文字或识别过程。
- 新图片导入或清除后，旧识别结果同步清空。
- 切换到“对局昵称”，导入包含完整左下角队伍栏的游戏截图，点击“读取昵称”，显示两名队友和本人所在区域的昵称。
- 读取昵称后在本次运行中保留“本场名单”，点击“选择同场结算并关联”手动选定同一局结算图，展示对应的玩家与战绩。
- 名单和结算顺序可以不同；匹配使用昵称候选与相似度做一对一分配。重复或近似候选、完全遮挡时保留待核对，不按卡片位置或剩余人数强行分配；仅认出本人不能证明整队对应。
- “清除预览”保留顶部可见的本场名单；“新对局”清空名单、图片和结果。读取新对局截图前旧名单会失效，退出程序后名单不会保留。
- 结算识别或关联完成后，点击“保存战绩”，将本场三人的数据与来源截图保存到本地；仅读取局内昵称时不能保存为战绩。
- 右上角“历史记录”可查看保存列表、三名玩家的数值、昵称关联状态、结算截图和关联时的局内截图。重启软件后仍可查看。
- 完全相同的截图按内容去重；补全昵称后再次保存会更新同一条记录，不生成第二条。普通未关联识别不会覆盖已有更完整的昵称关联。不同截图即使来自同一局，目前不会自动合并。

旧 WPF 版的编号结算图回归记录已归档，不对应当前 image_for_test 内容。当前 Rust 样本范围和验证结果见 [自动采集流程计划](docs/自动采集流程计划.md) 与 [阶段 D 说明](docs/Rust阶段D自动监测.md)。原图是小样本验证，不能据此宣称通用识别准确率或零漏抓。

### 对局昵称样本

旧 WPF 版本使用的 HUD 与结算昵称图已从测试目录移除。当前自动流程分别读取新 01 选传奇图和新 02 局内 HUD 图，并在 03 结算图核对昵称。

昵称入口依赖本机简体中文 Windows OCR 支持，不读取游戏内存，也不请求远程 OCR 服务。手动模式的待关联名单在内存中缓存；自动模式由本局上下文管理，并在结算时连同证据保存。匹配阈值和页面检测仍属于小样本原型规则，云端存储尚未实现。

### WPF 版本地数据

- 通过根目录 `启动.cmd` 或项目内 `dotnet run` 启动时，数据目录为项目根目录 `data/`；数据库为 `data/matches.db`，截图副本在 `data/screenshots/`。
- 识别成功后保留与结果对应的图像快照，保存不依赖原文件继续存在，不修改原文件。
- 时间字段明确标为“保存时间”（北京时间），并非精确的对局开始或结束时间。
- 未识别出的数值以数据库空值保存，和真实的 0 区分；未确认的昵称、本人的归属不会伪装成已确认。
- 战绩与三名玩家在同一事务中写入；保存失败会提示，不生成部分玩家的可见记录。同一截图先普通保存、再补充关联可更新，首次保存时间保持不变。
- 若要手工备份，先关闭软件，再复制整个 `data/` 目录。仅复制数据库不包含来源截图。该目录已加入 Git 忽略规则。
- 测试使用 `.local/storage-tests/` 中的隔离数据库，不向正式 `data/` 写入测试战绩。

当前仅对现有默认 HUD 样本做验证，尚未验证更长昵称、观战、其他 HUD 缩放或更多语言。底部“本人”指当前参考图中的本人区域；未据此确认真实账号身份。

## WPF 版运行

环境：Windows、.NET 10 SDK；“对局昵称”还需要本机已有简体中文 OCR 语言支持（当前开发机器已具备）。

双击项目根目录的 `启动.cmd`，或在项目目录运行：

```powershell
dotnet run --project .\BetterApex\BetterApex.csproj --configuration Release
```

旧 WPF 版检查步骤依赖已经移除的编号样本，不再适用于当前目录。Rust 版使用说明与游戏电脑验收步骤见 [Rust 自动记录测试说明](docs/自动记录测试说明.md)。
