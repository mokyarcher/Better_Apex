# Better Apex

Apex 玩家的本地战绩工具。当前主程序使用 **Rust + Tauri 2 + Vue 3**，通过低频 DXGI 采集与本地 OCR 自动记录结算，保存到独立 SQLite 和来源截图目录；不上传云端，不读取游戏内存，不导入旧 WPF 数据。

更新日期：2026-11-01。用户反馈：此前版本经过长时间实际游戏测试，暂未发现问题。新增“保存后自动下一局”已完成代码、回归和正式构建，实际游戏按键接收效果尚待用户确认；不将此前稳定性反馈视为新功能已验收。

## 当前功能

- **自动记录**：00 加载 → 01 选传奇 → 02 局内 → 03 结算 → 本地历史。常规每2秒最多一帧，结算确认临时每秒最多一帧；切出或最小化暂停，恢复后继续本局，结算停留不重复保存。
- **局内昵称**：01只监视阶段；02连续两帧确认HUD后仅读取一次三人昵称，不投票、不重试，空结果保留未知。最终自动昵称只来自同局02名单，03卡片文字只用于一对一匹配，不能补名或兜底保存。
- **结算识别**：选择PP-OCRv6 small时，排名、小队总击杀、三人击杀／助攻／击倒／伤害及卡片匹配线索使用同一PP实例。自动复核两帧只读数字，确认后才读取一次卡片线索；原Windows OCR + Tesseract仍可选。切换引擎前需停止自动记录，设置重启保留。
- **识别失败处理**：未知数字不填0。伤害未知或冲突时最多追加3张新结算帧；未完成结算也继续检测下一局00／01，避免停留在旧03，且不沿用上一局名单。支持完整16:9的1080P／2K输入，无需手动切换分辨率。
- **自动下一局（默认开启）**：完整结算数字自动保存成功后，再确认一张新鲜结算帧和可用的重新匹配提示，每局最多按一次主键盘数字`1`。设置中可关闭；切出、停止、关闭开关、画面变化、修饰键按住或确认超时则跳过，不补按。手动保存、历史恢复、去重和含未知数字的战绩不会触发。
- **游戏状态浮窗 Display**：可选开启，显示记录阶段、暂停／重试／按键结果、软件自身CPU与专用内存；包含WebView2子进程，每2秒采样。支持上／下居中、不透明度、鼠标穿透和15秒预览，切出游戏隐藏。内存目前统计专用提交量，与任务管理器默认工作集口径不同；尚未改成工作集。适用于窗口化／无边框，独占全屏可见性不作保证。
- **历史与手动补录**：自动保存后刷新历史、数量和最近一场，查看旧详情时保留选中项；支持手动截图识别、人工关联与保存。未知身份保留待核对，证据图随记录保存在本地。
- **后台运行**：单主窗口、托盘与单实例。自动记录运行中关闭主窗口会收至托盘；托盘可打开窗口或退出。
- **临时调试日志**：每次运行默认开启，在新版数据目录`nickname-debug/`生成TXT＋JSONL，记录实际OCR、空结果／错误、数字与昵称关联、保存及自动下一局结果；不覆盖、不自动清理、不上传，也不额外保存逐帧截图。

## 运行与交付

当前直接运行版：

```text
D:\GitCode\myproject-d\Better_Apex\.local\BetterApex-Rust-AutoRecord\BetterApex-Rust-AutoRecord.exe
```

复制EXE时必须一起复制同目录完整的`resources/`，包含PP-OCR模型、运行库和许可。游戏电脑无需安装Rust、Node.js或Python。旧Setup不会自动随直接运行版更新；只有明确要求时才重新生成Setup或ZIP。

正式构建使用项目根目录的`scripts/Publish-RustPortable.ps1`，自动构建前端，以Tauri `custom-protocol`嵌入页面。普通`cargo build --release`不能替代正式发布。

## 验证状态与开发约定

最近已完成45项Rust回归、3项前端测试及前端生产构建／正式Release。此前PP与原引擎对14张结算图各196个数字字段均通过；这些静态样本不能证明总体精度或游戏FPS收益。自动下一局测试验证了触发条件、取消、单次动作与按键结构，**没有向真实游戏或其他程序发送测试按键**。

按用户最新要求：**不再操控桌面跑测试或启动程序做UI验收**。默认只做与变更直接相关的必要代码检查、命令行验证和编译；不反复跑完整套件，不为文档改动编译或测试。游戏交互、按键接收与实际性能由用户实测。最新自动下一局构建未做桌面启动验收，应如实说明，不能沿用旧版启动截图作为本版证明。

需要命令行验证时复用现有缓存，按改动选择命令，不要求每次全部执行：

```powershell
$env:CARGO_TARGET_DIR = Join-Path $PWD '.local/rust-target-gui'
cargo test --manifest-path rust-app/src-tauri/Cargo.toml --lib --offline
cd rust-app
npm.cmd test
npm.cmd run build
```

## 文档与目录

- `rust-app/`：当前主程序；[开发说明](rust-app/README.md)。
- `docs/`：设计、阶段与使用说明；重点见[自动流程](docs/自动采集流程计划.md)、[阶段D](docs/Rust阶段D自动监测.md)、[OCR说明](docs/可选OCR引擎.md)和[浮窗说明](docs/游戏状态浮窗.md)。
- `assets/tesseract/tessdata/`：可选 Tesseract 引擎的语言模型和许可。
- `image_for_test/`：流程截图样本和反馈原图；不同队伍不能当作同局连续证据。
- `scripts/`：OCR 资源准备、便携版发布等当前辅助脚本。
- `rust-app/tests/` 与 `rust-app/src-tauri/`：当前前端与 Rust 测试。
- 根目录 `data/`：本机保留的旧战绩（Git 忽略）；新版数据位于 Tauri 应用本地目录，两版互不读写。
- `.local/`：本机编译缓存、依赖、隔离测试结果和当前运行版；不应整目录删除。
- `artifacts/`：本机历史安装包／压缩包（Git 忽略）。

旧版 WPF 源码与专用验证工具已从工作区移除。实现经验、仍复用的 Tesseract 资源和旧战绩边界见[旧版经验与迁移边界](docs/旧版经验与迁移边界.md)。历史迁移阶段文档用于理解决策背景；当前开发入口以 `rust-app/README.md` 和现行流程文档为准。

产品规划见[产品计划书](docs/产品计划书.md)。自动采集状态和验收边界见[自动采集流程计划](docs/自动采集流程计划.md)与[阶段 D](docs/Rust阶段D自动监测.md)。
